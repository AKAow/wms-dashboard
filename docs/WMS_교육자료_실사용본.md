# WindTree WMS 통합 교육자료 (실사용본)

교육 대상: 관리자 + 사용자
교육 시간: 60분
교육 목적: 시스템 운영 표준화, 역할별 실무 숙련, 장애 대응 내재화

---

## 1. 교육 목표

1) WMS 데이터 흐름을 설명할 수 있다.
2) 관리자/사용자 역할에 맞는 화면 기능을 수행할 수 있다.
3) 업로드 실패/조회 오류 발생 시 표준 절차로 대응할 수 있다.

---

## 2. 시스템 개요

### 2-1. 시스템 구성
- 화면: Next.js 기반 대시보드
- 인증/DB: Supabase
- 자동 처리: Cloudflare Worker
- 파일 변환: NRG Cloud API
- 자동 수집: Gmail API

### 2-2. 데이터 처리 흐름
1) RLD 파일 수집
- 수동: 사이트 관리 화면에서 업로드
- 자동: Gmail 검색 규칙으로 첨부파일 스캔

2) 변환/파싱
- Worker가 RLD를 변환 요청
- 변환 결과에서 측정값 파싱

3) 저장
- measurements: 시계열 원시 데이터
- daily_stats: 일별 통계
- upload_history: 처리 결과 이력

4) 조회
- 대시보드/데이터관리에서 사이트별 현황 확인

---

## 3. 핵심 데이터 구조

### 3-1. 주요 테이블
- sites: 사이트 정보, 동기화 설정
- user_site_access: 사용자별 사이트 접근권한
- measurements: 10분 단위 데이터
- daily_stats: 일별 통계 데이터
- upload_history: 업로드 성공/실패 기록

### 3-2. 채널 구성(예시)
- 풍속: ch1 ~ ch8
- 풍향: ch13 ~ ch16
- 기압/습도/온도: ch17, ch21, ch22

---

## 4. 권한 정책

### 4-1. 역할 정의
- 관리자(admin)
  - 전체 사이트 조회/관리
  - 설정 변경 가능
- 사용자(viewer)
  - 권한 부여된 사이트만 조회

### 4-2. 운영 원칙
- 권한 없는 데이터는 보이지 않는 것이 정상
- 사이트가 비활성 상태면 데이터 조회 제한 가능
- 권한 변경 후 실제 화면에서 즉시 검증 필수

---

## 5. 관리자 교육 파트

### 5-1. 사이트 관리
- 수동 추가
  - 필수: 사이트명, 사이트번호
  - 선택: 위치, 좌표, 고도, iPack 이메일
- RLD로 추가
  - 파일명 기반 사이트번호 인식
  - 신규 사이트 자동 생성 가능

### 5-2. 자동 동기화 설정
- 사이트별 동기화 ON/OFF
- 사이트별 Gmail 검색조건 설정 가능
- 주기: 주 1회 06:00 (설정값 기준)

### 5-3. 운영 모니터링
- 업로드 이력에서 상태 확인
  - success: 정상 반영
  - failed: 원인 파악 및 재처리
- 사이트별 최근 반영 시각 점검

### 5-4. 관리자 체크포인트
- 실패 건 0건 유지 목표
- 동일 실패 반복 시 공통 원인 문서화
- 월 1회 권한 정합성 점검

---

## 6. 사용자 교육 파트

### 6-1. 대시보드 활용
- 전체 사이트/활성 사이트/최근 업데이트 확인
- 사이트별 상태 신호 확인

### 6-2. 데이터관리 활용
- 사이트 필터로 이력 조회
- 상태별 처리 현황 확인
- 최근 실패 건 우선 확인

### 6-3. 사용자 행동 기준
- 데이터 이상 발견 시 즉시 관리자 공유
- 조회 오류는 권한/사이트 상태 먼저 확인
- 숫자만 보지 말고 업로드 이력 함께 확인

---

## 7. 실습 자료

### 실습 1. 사이트 상태 확인
목표: 사이트별 최신 반영 시간 확인
절차:
1) 대시보드 접속
2) 임의 사이트 선택
3) 최근 업로드 시간 확인
완료 기준: 최신 반영 시각을 말로 설명 가능

### 실습 2. 업로드 이력 분석
목표: 실패 건 식별 및 원인 추정
절차:
1) 데이터관리 이동
2) 사이트 필터 적용
3) 실패 건 1건 선택
4) 원인 가설 제시
완료 기준: 실패 원인 1개 이상 설명 가능

### 실습 3. 동기화 설정 확인(관리자)
목표: 설정 위치/항목 숙지
절차:
1) 설정 화면 이동
2) 동기화 요일 확인
3) 사이트별 동기화 ON/OFF 확인
완료 기준: 설정 변경 위치를 즉시 찾을 수 있음

---

## 8. 장애 대응 자료

### 8-1. 증상별 대응표

1) 업로드 실패
- 확인: upload_history 오류 메시지
- 점검: Worker 상태, 변환 API 응답, 파일형식
- 조치: 재처리 후 결과 확인

2) 데이터 미조회
- 확인: 사용자 권한, 사이트 활성 상태
- 점검: 해당 날짜 데이터 존재 여부
- 조치: 권한 수정/데이터 재반영 요청

3) 자동동기화 미실행
- 확인: 스케줄 설정, Gmail 토큰 상태
- 점검: 사이트별 sync enabled 여부
- 조치: 설정 복구 후 다음 주기 모니터링

### 8-2. 장애 보고서 템플릿
- 발생 시간
- 영향 사이트
- 증상
- 1차 원인
- 임시 조치
- 영구 조치
- 재발 방지 항목

---

## 9. 운영 체크리스트

### 일일 체크
- 최근 업로드 성공/실패 확인
- 핵심 사이트 최신 반영 시간 확인
- 실패 건 조치 여부 확인

### 주간 체크
- 자동동기화 실행 결과 점검
- 반복 실패 패턴 확인
- 권한 변경 내역 검토

### 월간 체크
- 관리자/사용자 권한 감사
- 사이트 메타정보 정확성 점검
- SOP 업데이트

---

## 10. 자주 묻는 질문

Q1. 사이트는 보이는데 데이터가 안 보입니다.
- 권한, 사이트 활성상태, 날짜 데이터 유무 순으로 확인

Q2. 같은 파일을 다시 올리면 중복 저장되나요?
- 업로드 이력 기준 중복 방지 로직으로 중복 처리 회피

Q3. 동기화 요일 바꾸면 바로 실행되나요?
- 즉시 실행이 아니라 다음 스케줄부터 반영

Q4. 사용자 초대가 안 됩니다.
- 현재 UI 준비 상태일 수 있으므로 서버 초대 연동 여부 확인 필요

---

## 11. 교육 종료 기준

- 관리자: 사이트 등록/동기화/이력 점검을 독립 수행 가능
- 사용자: 대시보드 조회 및 이상 징후 보고 가능
- 공통: 장애 발생 시 표준 템플릿으로 보고 가능
