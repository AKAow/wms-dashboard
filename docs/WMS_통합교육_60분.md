## 2. 시스템 한눈에 보기

### 2-1. 목적

- 기상 측정 데이터(RLD)를 안정적으로 수집/변환/저장/조회
- 사이트별 권한 기반 데이터 제공
- 운영 현황(업로드 성공/실패, 최근 반영) 가시화

### 2-2. 기술 스택

- Frontend: Next.js 14, TypeScript, Tailwind
- DB/Auth: Supabase (PostgreSQL + Auth)
- Worker: Cloudflare Workers
- 변환: NRG Cloud API
- 메일 수집: Gmail API (스케줄 동기화)

### 2-3. 데이터 흐름

1) 파일 유입
- 수동 업로드: 사이트 관리에서 RLD 업로드
- 자동 동기화: Gmail에서 사이트 규칙 기반 첨부파일 스캔

2) 변환
- Worker가 NRG API에 RLD 변환 요청
- 압축 해제 후 meas 텍스트 파싱

3) 저장
- `measurements`에 10분 단위 원시 데이터 저장 (중복 merge)
- `daily_stats`에 일별 채널 통계(평균/최대/최소/표준편차) 저장
- `upload_history`에 처리 결과 이력 저장

4) 조회
- 대시보드/데이터관리 화면에서 사이트별 현황 및 이력 조회

---

## 3. 데이터 모델 핵심

### 3-1. 주요 테이블

- `sites`: 사이트 기본정보, Gmail 동기화 설정
- `measurements`: 시계열 원시 데이터 (site_id + timestamp 유니크)
- `daily_stats`: 일별 채널 통계 (site_id + date + channel 유니크)
- `upload_history`: 적재 이력(성공/실패/건수/파일명)
- `user_site_access`: 사용자-사이트 접근권한

### 3-2. 채널 예시

- 풍속: ch1~ch8
- 풍향: ch13~ch16
- 기압/습도/온도: ch17/ch21/ch22

---

## 4. 권한/보안 로직

### 4-1. 역할

- Admin: 전체 사이트 접근 및 관리
- Viewer: 권한 부여된 사이트만 조회

### 4-2. 정책 포인트(RLS)

- `sites`, `measurements`, `daily_stats`는 RLS 활성화
- 관리자: 전체 접근 허용
- 일반 사용자: `user_site_access` 매핑된 사이트만 접근

### 4-3. 운영 주의

- 관리자 계정 메타데이터(role=admin) 정확히 유지
- 사이트 권한 부여/회수 시 즉시 검증

---

## 5. 관리자 파트 (10~25분)

## 5-1. 사이트 관리

- 수동 추가
  - 사이트명, 사이트번호 필수
  - 위치/좌표/고도/iPack 이메일 입력 가능
- RLD로 추가
  - 파일명에서 사이트 번호 자동 인식
  - 신규 사이트면 자동 생성

## 5-2. 사이트별 Gmail 동기화 설정

- `gmail_sync_enabled` ON/OFF
- `gmail_query` 지정 가능
  - 비어있으면 기본 규칙 사용(사이트 번호 기반)

## 5-3. 데이터 관리

- 자동 동기화 주기 확인/변경 (주 1회 06:00 KST)
- 사이트별 업로드 성공/실패 현황 확인
- 실패 건 원인 파악 후 재처리

## 5-4. 사용자 관리

- 현재 UI: 권한 목록 조회/초대 화면
- 주의: 초대 메일 실제 발송은 서버 함수 연결 필요(현재 안내성 상태)

---

## 6. 사용자 파트 (25~40분)

## 6-1. 대시보드 해석

- 전체 사이트/활성 사이트/최근 업데이트 일자 확인
- 사이트별 상태 점검
- 최근 업로드 목록에서 정상 반영 여부 확인

## 6-2. 데이터관리 화면

- 자동 동기화 상태 확인
- 사이트 필터로 업로드 이력 조회
- 상태 아이콘으로 실패 건 우선 확인

## 6-3. 사용자 실수 Top 4

1) 내 권한 없는 사이트 데이터를 찾음
2) 동기화 주기를 즉시 반영으로 오해
3) 실패 이력 확인 없이 대시보드 숫자만 신뢰
4) 파일명 규칙 불일치 RLD 업로드

---

## 7. 실습 (40~50분)

## 실습 1) 사이트 현황 확인

- 목표: 사이트 목록과 최근 업로드 확인
- 절차
  1. 대시보드 진입
  2. 특정 사이트 선택
  3. 최근 반영 시각 확인

## 실습 2) 업로드 이력 필터링

- 목표: 사이트별 성공/실패 추적
- 절차
  1. 데이터관리 > 사이트 필터 선택
  2. 최근 실패 건 1건 찾기
  3. 처리 필요 여부 판단

## 실습 3) 관리자 설정 점검

- 목표: 동기화 설정 값 확인
- 절차
  1. 설정 > 동기화 요일 확인
  2. 사이트 관리 > Gmail 동기화 ON/OFF 확인

## 8. 장애 대응 표준 (SOP)

## 8-1. 증상별 1차 대응

A. 업로드가 안 됨
- Worker 상태 확인
- NRG 토큰/변환 API 응답 확인
- upload_history 실패 메시지 확인

B. 데이터가 안 보임
- 사용자 권한 확인(user_site_access)
- 사이트 활성 상태 확인(is_active)
- 해당 날짜 데이터 존재 여부 확인

C. 자동 동기화 미동작
- cron 요일 설정 확인
- Gmail OAuth 토큰 갱신 상태 확인
- 사이트별 gmail_sync_enabled 확인

## 10. Q&A 가이드

Q1. 왜 사이트는 보이는데 데이터가 안 보이나요?
- 권한/활성 상태/해당일 데이터 유무를 순서대로 확인

Q2. RLD 업로드 했는데 중복 처리되나요?
- 업로드 이력(file_name) 기반으로 중복 방지 로직 적용

Q3. 동기화 주기를 바꾸면 즉시 실행되나요?
- 주기 변경은 다음 스케줄부터 적용, 즉시 실행은 별도 트리거 필요

Q4. 사용자 초대가 동작 안 해요.
- 현재 화면은 준비 단계, 서버 함수 연결 후 실발송 활성화 필요
