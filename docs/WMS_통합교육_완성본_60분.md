# WindTree WMS 통합 교육자료 완성본 (60분)

대상: 관리자 + 사용자 통합 교육  
버전: v1.0 (운영 배포본)  
목표: 실무에서 바로 운영 가능한 수준의 사용/관리/장애대응 역량 확보

---

## 1. 교육 목표

이번 교육 종료 시점에 수강자는 아래를 수행할 수 있어야 합니다.

1) WMS 전체 흐름(수집 → 변환 → 저장 → 조회)을 설명할 수 있다.  
2) 관리자/사용자 역할에 맞게 핵심 기능을 독립적으로 수행할 수 있다.  
3) 장애 발생 시 표준 절차(SOP)로 원인 확인과 보고를 할 수 있다.

## 3. 시스템 개요

### 3-1. 시스템 목적
- RLD 기반 기상/운영 데이터를 일관되게 수집하고 표준화한다.
- 사이트별 권한에 맞는 데이터만 안전하게 제공한다.
- 운영자가 문제를 빠르게 탐지/조치할 수 있도록 이력을 제공한다.

### 3-2. 기술 구성
- Frontend: Next.js 14, TypeScript
- Backend/Auth/DB: Supabase (PostgreSQL + RLS)
- 자동처리: Cloudflare Worker
- 변환: NRG Cloud API
- 자동수집: Gmail API

### 3-3. 데이터 흐름
1) 파일 수집
- 수동: 사이트 관리에서 RLD 업로드
- 자동: 사이트별 Gmail 규칙으로 첨부 스캔

2) 변환/파싱
- Worker가 RLD를 NRG API로 변환 요청
- 변환 결과를 파싱하여 측정값 추출

3) 저장
- measurements: 원시 시계열 데이터
- daily_stats: 일별 통계(평균/최대/최소/표준편차)
- upload_history: 성공/실패/파일/건수 이력

4) 조회
- 대시보드/데이터관리에서 사이트별 상태와 이력 확인

---

## 4. 데이터/권한 구조 핵심

### 4-1. 주요 테이블
- sites: 사이트 메타정보, 동기화 설정
- user_site_access: 사용자-사이트 접근권한
- measurements: 10분 단위 측정 데이터
- daily_stats: 일별 집계 통계
- upload_history: 업로드 처리 이력

### 4-2. 권한 정책
- Admin: 전체 사이트 조회/관리
- Viewer: 권한 부여된 사이트만 조회
- RLS 기반으로 데이터 노출을 강제 분리

### 4-3. 운영 원칙
- 권한이 없으면 안 보이는 것이 정상
- 비활성 사이트는 운영 대상에서 제외 가능
- 권한 변경 후 즉시 화면 검증 필수

---

## 5. 관리자 실무 가이드

### 5-1. 사이트 관리
- 수동 등록: 사이트명/사이트번호 필수
- RLD 등록: 파일명 기반 사이트번호 인식, 신규 사이트 자동 생성 가능
- 사이트 상태: 활성/비활성 관리

### 5-2. 자동 동기화 관리
- 사이트별 gmail_sync_enabled 설정
- 사이트별 gmail_query 커스터마이징 가능
- 스케줄(주 1회 06:00) 정상 동작 여부 점검

### 5-3. 업로드 이력 운영
- status=failed 건 우선 확인
- error_message 기준 원인 분류
- 재처리 후 성공 여부 재검증

### 5-4. 관리자 필수 점검 포인트
- 반복 실패 원인 문서화
- 월 1회 권한 감사
- 사이트 메타정보(번호/좌표/활성) 정합성 유지

---

## 6. 사용자 실무 가이드

### 6-1. 대시보드 확인 순서
1) 전체 사이트 / 활성 사이트 수 확인
2) 최근 업데이트 시각 확인
3) 사이트별 상태 확인

### 6-2. 데이터관리 확인 순서
1) 사이트 필터 적용
2) 최근 업로드 성공/실패 확인
3) 실패 건 발생 시 관리자에게 즉시 공유

### 6-3. 사용자 실수 방지
- 숫자만 보고 정상 판단 금지
- 반드시 업로드 이력 상태와 함께 확인
- 권한 문제 발생 시 데이터 결함으로 오판 금지

## 7. 실습 시나리오 (10분)

### 실습 1: 사이트 상태 확인 (3분)
- 목표: 특정 사이트 최근 반영 시간 파악
- 완료 기준: 반영 시각과 상태를 구두로 설명

### 실습 2: 실패 건 추적 (4분)
- 목표: 실패 건 1건 찾고 원인 가설 제시
- 완료 기준: 원인 1개 + 조치 1개 제안

### 실습 3: 설정 위치 찾기 (3분)
- 목표: 동기화 설정/권한 관련 메뉴 위치 숙지
- 완료 기준: 담당 메뉴를 10초 내 탐색

## 8. 장애 대응 SOP

### 8-1. 증상별 1차 조치

A. 업로드 실패
- 확인: upload_history status, error_message
- 점검: Worker 상태, NRG API 응답, 파일 형식
- 조치: 재처리 후 성공 여부 확인

B. 데이터 미조회
- 확인: user_site_access 권한
- 점검: 사이트 활성 상태, 날짜 데이터 존재 여부
- 조치: 권한 보정 또는 데이터 재반영 요청

C. 자동동기화 미실행
- 확인: cron 설정, Gmail 토큰 상태
- 점검: 사이트별 sync_enabled
- 조치: 설정 복구 후 다음 주기 모니터링

### 8-2. 장애 보고 템플릿
- 발생시각
- 영향 사이트
- 증상
- 1차 원인
- 임시 조치
- 영구 조치
- 재발 방지

## 9. 운영 체크리스트

### 일일
- 최근 업로드 성공/실패 확인
- 핵심 사이트 최신 반영시각 확인
- 실패 건 당일 조치 여부 확인

### 주간
- 자동동기화 정상 실행 여부 점검
- 반복 실패 패턴 확인
- 권한 변경 이력 검토

### 월간
- 관리자 계정/권한 감사
- 사이트 메타정보 정합성 점검
- SOP 업데이트

## 10. 자주 묻는 질문 (FAQ)

Q1. 사이트는 보이는데 데이터가 없어요.  
A. 권한 → 사이트 활성상태 → 해당일 데이터 유무 순서로 점검합니다.

Q2. 같은 파일을 다시 업로드하면 중복 저장되나요?  
A. 업로드 이력 기준으로 중복 방지 로직이 적용됩니다.

Q3. 동기화 요일을 바꾸면 즉시 반영되나요?  
A. 다음 스케줄 실행부터 반영됩니다.

Q4. 사용자 초대가 안 됩니다.  
A. UI/서버 초대 연동 상태를 확인해야 하며, 연동 전이면 실제 발송은 제한됩니다.
